# リールの自動編集(動画編集スキル)

良し悪しの判断は必ず `reel-judgment` スキル(判断基準)に従う。ここには「どうやるか・どの順番か」だけを書く。
道具は `scripts/reel.py`(FFmpeg + faster-whisper)。型は `kata/*.json`。

## 作業フォルダ
リポジトリ直下の `reel-edit/`:
- `参考例/` …「こうなりたい」動画(分析に使うだけ。映像・音源は自分の動画に使わない)
- `素材/` … 自分の撮りっぱなしの動画(30秒〜1分。声がはっきり)
- `書き出し/` … 計画(`*.plan.json` / `.md`)と書き出した動画
- 動画・文字起こし・計画は `.gitignore` 済み。**公開リポジトリなので動画や文字起こしをコミットしない。**

以下、`R=.claude/skills/reel-edit/scripts/reel.py`、`K=.claude/skills/reel-edit/kata/kata-a.json`。

## 0. 道具を確かめる・入れる
```bash
python3 $R check
```
- NG があれば入れ方を一覧で見せて、ユーザーの OK を待ってから入れる。**パスワードはユーザーが自分で入れる**(聞かない)。
  - FFmpeg: Mac `brew install ffmpeg` / Windows `winget install Gyan.FFmpeg` / Linux `sudo apt install ffmpeg`
  - Whisper: `pip install -r .claude/skills/reel-edit/requirements.txt`(faster-whisper。初回の文字起こしでモデル約 500MB(small)をダウンロード)
  - 日本語フォント: 無ければ Noto Sans CJK JP を入れる(テロップが □□□ になるのを防ぐ)
- Claude Code on the web(クラウド)では FFmpeg は入っているが、Whisper のモデル配布元(huggingface.co)がネットワーク設定でブロックされていることがある。そのときは環境の Network access に `huggingface.co` を足してもらうか、ユーザーの PC で実行する。
- 動いた証拠は返事ではなくファイル。5秒だけ書き出して確かめる:
```bash
python3 $R clip reel-edit/素材 -o reel-edit/書き出し --seconds 5
python3 $R transcribe reel-edit/書き出し/<名前>_最初の5秒.mp4
```

## 1. 参考例を分析して型を作る
```bash
python3 $R analyze reel-edit/参考例 -o reel-edit/書き出し/参考例_分析
python3 $R transcribe reel-edit/参考例   # 話す速さ・冒頭の言葉を見るため
```
- `analysis.json` の数字(カット数・平均カット秒数・無音の長さ・音量)と、`frames/` のコマ画像を**実際に見て**、5つを表にする。できるだけ数字で、分からない所は「不明」と書く。
  | 項目 | 見ること |
  | --- | --- |
  | テンポ | 1カット平均何秒か、何秒以上の間を詰めているか |
  | テロップ | 位置(画面の下3分の1 など)・大きさ・色・フチ・1行の文字数・出るタイミング |
  | 動き | ズーム・切り替えをどこで使うか |
  | 音 | BGM と効果音の大きさ・入れる場所(声との差は耳で確かめられないので推定と書く) |
  | 冒頭 | 最初の1秒で何を見せているか |
- 表をユーザーに見せ、違う所だけ言葉で直してもらう(8割合っていれば OK)。
- OK が出たら `kata/kata-a.json` の数字を書き換え、`status` を「確定」、`source` に参考例の説明(ファイル名や URL は書かない)を入れる。別の型にするときは `kata-b.json` などを作り、下の「型の一覧」に足す。
- 参考例は慣れたら3本、10本と増やすほど精度が上がる(平均を取る)。

## 2. 素材を編集する(いきなり書き出さない)
```bash
python3 $R transcribe reel-edit/素材 --prompt "固有名詞のヒント"
python3 $R plan reel-edit/素材 --kata $K --transcript reel-edit/素材/<名前>.transcript.json \
  --hook "冒頭に大きく出す結論" [--bgm <BGMファイル>] -o reel-edit/書き出し/<名前>.plan.json
```
1. 文字起こしを読み、判断基準に沿って計画を整える。`plan.json` を直接直す:
   - `keep`(残す元動画の区間 [開始, 終了] 秒)… 言い直し・言い間違い・関係ない話を区間ごと削る。
   - `telops` … 誤字・聞き間違いを直す。要点だけに短くする(全部を字幕にしない)。1行12文字以内。
   - `hook.text` … 冒頭1秒で見せる結論(最初のテロップのままにしない)。
   - `bgm.file` … ユーザーが用意した、使ってよい音源だけ。参考例の音源は使わない。
2. **計画の表(切るところ・テロップの文言・冒頭・BGM)をユーザーに見せて OK を待つ。** テロップの誤字はここで直す(書き出しは重い、計画は軽い)。
3. OK が出たら書き出す:
```bash
python3 $R render reel-edit/書き出し/<名前>.plan.json -o reel-edit/書き出し
```
4. 終わったら「何を作ったか・どこに保存したか・次にユーザーがやること」を3行で報告する。

## 3. 採点して直す
- 書き出した動画を `analyze` にかけ、数字を型と比べる。コマ画像も見る。`reel-judgment` の採点のものさしで100点満点で採点。70点未満なら原因と直し方を3つまで出して直す。
- ユーザーからの直しは「何秒の・何を・どうする」で受ける(例:「0:12〜0:15 の“えーと”を切る」「テロップを一回り大きく」「BGM を今の半分に」)。1回に2〜3個まで。
  - 時間の指定は書き出した動画の時間。`plan.json` は元動画の時間なので、`keep` を前から足して換算する。
  - 大きさ・色・音量は型の JSON、文言・区間は `plan.json` を直す。
- 直したら、次から最初に反映されるように**型の JSON と下の「型の一覧」のメモに追記する**。判断基準は「そもそも」が変わったときだけ直す。

## 止まったとき
| 症状 | 対処 |
| --- | --- |
| 書き出しが終わらない | 素材を短くする(まず15秒)。`--preset veryfast` |
| テロップが □□□ | 日本語フォントを入れる。`check` で確認(無いフォントは自動で別の日本語フォントに置き換わる) |
| Whisper のモデルを読み込めない | ネットにつながる環境で実行。クラウドなら `huggingface.co` を許可 |
| 文字起こしの誤字が多い | `--prompt` に固有名詞を入れる。`--model medium` にする(遅くなる) |
| パスワードを聞かれた | ユーザーが自分で入力する |

## 型の一覧
- **型A**(`kata/kata-a.json`):仮。勉強会スライドの例の数字(1カット平均1.5秒、0.3秒以上の間はカット、テロップは下3分の1・白文字に黒フチ・1行12文字、区切りでズーム、BGM は声より小さく、最初の1秒で結論を大きく)。参考例を分析したら置き換える。
  - 直しの記録: (まだなし)
